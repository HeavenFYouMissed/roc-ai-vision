ONNX Runtime engine to be completely dynamic and able to read any ONNX model
the Model Dictate the DimensionsInstead of telling the model what size image you are giving it, your C++ engine should interrogate the ONNX file at boot.ONNX Runtime has a built-in metadata API. When your ROS 2 vision node loads the .onnx file, the very first thing it should do is query the input layer for its expected shape vector, which looks like this:$$\text{Shape} = [\text{Batch}, \text{Channels}, \text{Height}, \text{Width}]$$For example, a standard vision model will return $[1, 3, 640, 640]$ or $[1, 3, 1080, 1920]$. Your C++ code catches those integers dynamically and automatically configures your OpenCV preprocessing pipeline to match them.
 use Letterboxing (scaling the image while maintaining the original aspect ratio and padding the dead space with gray pixels).The Calculation LogicTo scale an arbitrary capture frame ($\text{src}$) to match an arbitrary ONNX input shape ($\text{dst}$), you calculate the scale factor ($s$):$$s = \min\left(\frac{\text{dst}_{w}}{\text{src}_{w}}, \frac{\text{dst}_{h}}{\text{src}_{h}}\right)$$You resize the original frame by $s$, and then pad the remaining width or height with flat color values (typically 114, 114, 114 for vision models) to fill out the exact required dimensions.
